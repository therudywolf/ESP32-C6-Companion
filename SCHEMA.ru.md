# Схема провода Ноктюрна

[English](SCHEMA.md) · **Русский**

Пакет устройства — это **JSON, разделённый переводами строк**, поверх TCP (хаб,
порт 8888) либо HTTPS (необязательный всегда включённый эндпоинт *lite*).
Производители обязаны договориться о нём:

| Производитель | Что отдаёт | Где |
|---|---|---|
| **хаб** (`NocturneServer`, `python -m hub`) | полный пакет по TCP | `payload.py :: build_payload()` |
| **эндпоинт lite** (любой хост, на который смотрит секция `[lite]` на карте) | ПОДМНОЖЕСТВО (погода + лес/сервисы + события + часы) по HTTPS | собственный `build_payload()` |
| **прошивка** (`ESP32-C6-Companion`) | потребитель — **канонический разбор** | `src/net/TelemetryClient.cpp :: parsePayload()` |

С v1.44.0 плата держит **два хаба** — основной и запасной, — но говорят они по
этой же схеме и из одной кодовой базы, так что договариваться не о чем
дополнительно: различие между ними в том, где они стоят, а не в том, что они
говорят.

> Источник истины — разбор в прошивке. Переименованное поле у производителя, не
> отражённое здесь, **молча рассинхронизирует плату** — особенно на эндпоинте
> lite, на который она опирается с выключенным ПК. Держите этот файл в согласии
> с `parsePayload()` и со всеми `build_payload()`.
>
> `tools/check_schema.py` следит за тем, за чем вообще можно уследить: каждый
> ключ, который читает прошивка, обязан быть назван **и в этом файле, и в его
> английском двойнике**. Перевод, тихо отставший от оригинала, хуже отсутствия
> перевода.

Строковые поля прошивка обрезает до размеров буферов, указанных ниже
(`copyStr`); отдавайте короче — и всё хорошо. Целые по умолчанию считаются
`-1`/`0`, когда их нет.

## Блоки, которые отдаёт и эндпоинт lite (должны совпадать точно)

### Погода (ключи верхнего уровня)
| ключ | тип | значение |
|---|---|---|
| `wt` | int | текущая температура °C |
| `wp` | int | вероятность осадков % |
| `wd` | string | краткое описание (`Clear`/`Rain`/…) |
| `wi` | int | код погоды WMO |
| `wf` | array | до 5 × `[tmin, tmax, wmocode]`, прогноз по дням |

### `clk`
Строка `"HH:MM"` (у платы есть и собственные часы по NTP; `clk` в пакете —
запасной вариант). Lite отдаёт московское время.

### `events` — `{n, top, sev, txt, list}`
| ключ | тип | размер | значение |
|---|---|---|---|
| `n` | int | | сколько тревог горит |
| `top` | string | ≤20 | имя самой тяжёлой тревоги (баннер) |
| `sev` | string | ≤11 | её тяжесть (`critical`/`warning`/`info`/`none`) |
| `txt` | string | ≤60 | человеческий текст (summary/description) |
| `list` | string[] | ≤4 × ≤20 | имена тревог для экрана со списком |

Порядок тяжести (по нему выбирается баннер): `critical > warning > info >
none`. Хаб собирает этот блок в `alert_events.build_events_block`; lite зеркалит
его из Alertmanager v2 `/api/v2/alerts` — держите обе реализации одинаковыми.

### `forest` — `{n, up, nodes:[…]}` (≤6 узлов)
узел: `{id, name, st, cpu, ram, disk, extra}`
| ключ | тип | размер | значение |
|---|---|---|---|
| `id` | string | ≤8 | устойчивый идентификатор узла — канонические **`srv`** и **`pc`**; производители обязаны совпасть, иначе плата переименует плитку при переходе на запасной |
| `name` | string | ≤16 | отображаемое имя (безопаснее латиницей: часть шрифтов для имён узлов только латинская) |
| `st` | string | ≤5 | `up` / `warn` / `down` (`warn` = доступен, но какой-то ресурс ≥90 %) |
| `cpu`,`ram`,`disk` | int | | проценты, **округлённые** (не усечённые), `-1` = неизвестно → плата рисует `--`, а не `0%` |
| `extra` | string | ≤16 | произвольная надпись-бейдж |

### `zb` — датчики умного дома `{n, list:[…]}` (≤4)
Показания для плитки ПОГОДА. С v1.14.0 **плата сама является координатором
Zigbee** (канал 25, +380 КБ флеша, единственный раздел приложения — OTA был
обменян на это) и заполняет показания локально с привязанных датчиков. Блок в
пакете при этом работает ровно как раньше, так что серверный производитель
(Zigbee2MQTT, Home Assistant, опрос хаба Яндекса) может кормить тот же экран на
платах, собранных без стека (`nocturne-c6-nozb`).

запись: `{name, t, h, b, age, p}`
| ключ | тип | размер | значение |
|---|---|---|---|
| `name` | string | ≤16 | подпись комнаты или датчика, видна на плитке ПОГОДА |
| `t` | int | | температура **×10** (23.6 °C → `236`); опускайте, когда неизвестна |
| `h` | int | | относительная влажность %, -1 = неизвестно |
| `b` | int | | заряд %, -1 = неизвестно; ниже 20 полоска краснеет |
| `age` | int | | секунд с последнего отчёта датчика, -1 = неизвестно |
| `p` | int | | атмосферное давление **гПа**, -1 = у этого датчика нет барометра |

> `age` не факультативен по смыслу. Батарейные датчики Zigbee молчат часами, и
> последнее известное показание, поданное как текущее, — та же ложь, ради
> которой существует обработка «нет сигнала». Старше часа — и вся плитка гаснет.

### `svc` — `{n, up, list:[…]}`
запись: `{name (≤18), st (up/down), ms (int, -1 = неизвестно)}`

### `dock` — `{n, up}`
счётчики контейнеров (lite может не отдать → устройство покажет 0).

### `src`
метка производителя, например `forest-lite`; lite дописывает `!wx`/`!forest`/
`!svc`, когда блок не удалось наполнить. Прошивкой игнорируется, полезна в логах.

## Блоки, которые отдаёт только хаб (у lite аналога нет)

`tools/check_schema.py` роняет сборку, если прошивка разбирает ключ, нигде здесь
не названный, — поэтому таблицы ниже перечисляют всё, а не пересказывают. Прежнее
«…» прятало десятка два полей, на которые плата реально реагирует.

### Скаляры железа (верхний уровень, все int, если не сказано иначе)
| ключ | значение | | ключ | значение |
|---|---|---|---|---|
| `ct` | температура CPU °C | | `gt` | температура GPU °C |
| `cl` | загрузка CPU % | | `gl` | загрузка GPU % |
| `cc` | частота CPU МГц | | `pw` | мощность пакета CPU Вт |
| `gh` | hotspot GPU °C | | `gv` | занято видеопамяти % |
| `gclock` | частота ядра GPU | | `vclock` | частота памяти GPU |
| `gtdp` | мощность GPU в % от TDP | | `ch` | температура чипсета °C |
| `ru` (float) | занято ОЗУ ГБ | | `ra` (float) | всего ОЗУ ГБ |
| `vu` (float) | занято видеопамяти ГБ | | `vt` (float) | всего видеопамяти ГБ |
| `nd` | сеть вниз кб/с | | `nu` | сеть вверх кб/с |
| `pg` / `ping` | пинг мс (любой из ключей) | | `dr` / `dw` | чтение/запись диска МБ/с |
| `cf` | обороты вентилятора CPU | | `gf` | обороты вентилятора GPU |
| `s1`, `s2` | обороты корпусных | | | |
| `mb_sys` | температура платы °C | | `mb_vrm` | температура VRM °C |
| `mb_vsoc` | температура по напряжению SoC | | `mb_chipset` | температура чипсета °C |
| `pidle` | секунд с последнего действия хозяина | | | |

Массивы: `fans` и `fan_controls` (по ≤4 int), `hdd` (≤4 записи вида
`{n (≤2 символа), u, tot (float, ГБ), t (int, °C)}`), `tp` (топ процессов по
CPU, ≤3 × `{n, c}` = имя и проценты), `tr` (топ процессов по ОЗУ, ≤2 ×
`{n, r}` = имя и МБ).

### `media`
`{art, trk, mp, idle, media_status, ctok, mpos, mdur}` — исполнитель, трек,
`mp` = играет ли (bool), `idle`, `media_status` (`PLAYING`/`PAUSED`), `ctok` =
токен обложки (его смена запускает перезагрузку картинки), `mpos`/`mdur` =
позиция и длительность в секундах. Сама обложка забирается отдельно с панели
управления, в формате RGB565.

### Перехват по тревоге (верхний уровень)
`alert` (`"CRITICAL"` взводит), `target_screen` (`MAIN`/`CPU`/`GPU`/`RAM`/
`DISKS`/`MEDIA`/`FANS`/`MOTHERBOARD`), `alert_metric`
(`ct`/`gt`/`cl`/`gl`/`gv`/`ram`, определяет надпись на баннере).

### `notif`
`{seq, app, title, body, pending, dur, led}` — всплывашка Windows, отзеркаленная
на карточку уведомлений устройства. **Обрезано** до app≤24 / title≤48 /
body≤160 символов: необрезанное тело выталкивало кадр за `NOCT_TCP_LINE_MAX`.

### `pc` — кормит ли хаб агент с ПК
`pc: 1`, когда у хаба свежая телеметрия от агента, `pc: 0`, когда агент молчит
дольше 12 с (ПК спит или выключен). При `pc: 0` ключей железа, медиа и процессов
**нет вовсе**; плата считает, что линк идёт без ПК (экраны, которым нужен ПК,
гаснут, а «последние данные N мин назад» отсчитываются от последнего пакета с
`pc: 1`), тогда как погода, лес, сервисы, события и `rc` продолжают идти. На
классическом однопроцессном сервере ключа нет.

### Прогноз по комнате (верхний уровень, рядом с ключами погоды)
Подгоняется на ПК (`roomcast.py`) и шлётся как ответ, а не как входные данные:
`rcok` (0/1 — модель существует), `rct3` / `rct12` (температура комнаты через
3 ч / 12 ч, десятые °C), `rcs3` / `rcs12` (одна сигма, десятые), `rch3` /
`rch12` (влажность %, -1 = не подогнана), `rco3` / `rco12` (улица в тот же час,
десятые; наличие `rco3` = `haveStreet`), `rcw` (почему ответа нет), `rcr` (одна
строка о вероятностном риске).

### `rc` — дистанционное управление (плата исполняет один раз на смену `seq`)
Все поля необязательны; сторожевое значение означает «в этот раз без изменений».

| ключ | тип | сторож | действие |
|---|---|---|---|
| `seq` | int | — | **обязателен**; именно его смена взводит весь блок |
| `screen` | int | -1 | перейти на сцену N |
| `say` | string | "" | заставить волка произнести эту строку дословно |
| `theme` | int | -1 | индекс пресета палитры |
| `bright` | int | -1 | подсветка, зажимается в 30..210 |
| `led` | 0/1 | -1 | диод настроения вкл/выкл |
| `ledmode` | 0..3 | -1 | стиль диода в покое: настроение / выкл / радуга / свеча |
| `carousel` | int | -2 | -1 = выкл, иначе интервал в секундах |
| `petllm` | 0/1 | -1 | разрешить волку пользоваться моделью |
| `wchat` | 0..3 | -1 | болтливость: выкл / редко / норма / часто |
| `wtone` | 0..3 | -1 | характер: обычный / добрый / ворчун / дерзкий |
| `flip` | 0/1 | -1 | повернуть экран на 180° |
| `timeout` | int | -1 | секунд до гашения экрана, 0 = выкл |
| `bgstyle` | 0..2 | -1 | фон: чистый / анимация / сетка |
| `bglight` | 0/1 | -1 | светлый фон |

| `uielem` | int | -1 | битовая маска необязательных классов виджетов |
| `action` | string | "" | `feed` / `play` / `pet` / `talk` |
| `chrome` | [r,g,b] | нет ключа | переопределить оттенок хрома |
| `accent` | [r,g,b] | нет ключа | переопределить оттенок акцента |
| `color` | [role,r,g,b] | нет ключа | задать одну роль палитры (0..9) |
| `palette` | 10 × [r,g,b] | нет ключа | задать палитру целиком |
| `resetcustom` | 1 | -1 | сбросить свою палитру, вернуться к пресету |
| `pin` | int | -2 | закреплённый «домашний» экран, -1 = логово |
| `slot` | 0..2 | -1 | переключить активный слот палитры |
| `night` | 0/1 | -1 | тихие часы вкл/выкл |
| `nightfrom`, `nightto` | 0..23 | -1 | границы тихих часов (переходят через полночь) |
| `zbalert` | 0/1 | -1 | климатические тревоги по датчику ForestHome |
| `zbtmin`, `zbtmax` | °C | -1000 | коридор температуры; `-99`/`99` отключают свою сторону |

> Четыре ключа `tone*` намеренно **не** однократные. Плата держит поправку
> только в ОЗУ, так что именно переигрывание с панели возвращает её после
> перезагрузки — калибровка под конкретную панель, которую пришлось бы вводить
> руками при каждом рестарте, не пережила бы и одной настоящей недели.

> **Про частоту опроса:** Aqara WSDCGQ11LM решает сам — он отчитывается по
> изменению (~±0.5 °C, ±6 % RH) плюс держит связь примерно раз в 50–60 минут, и
> именно этот ритм даёт CR2032 прожить два года. Слушает он только сразу после
> передачи, так что опрос в произвольный момент обычно не доходит ни до кого.
>
> `zbjoin`/`zbpoll` — события, а не настройки: панель убирает их из склеенной
> команды, вместо того чтобы повторять при следующем, ничем не связанном клике.
> `zbpoll` — это *просьба* (Aqara — спящее конечное устройство и отвечает по
> своему расписанию), и `zbint` тоже просьба: прошивки Xiaomi, как известно,
> игнорируют configure-reporting. Панель говорит об этом вслух, а не выдаёт их
> за настройки.

> Климатические ключи используют **-1000** в значении «в этой команде их нет», а
> не -1: любое обычное значение здесь — включая 0 и отрицательные — законный
> порог, так что привычный сторож сделал бы «предупреди меня ниже 0 °C»
> невыразимым. Тревоги срабатывают на ФРОНТЕ, с гистерезисом в градус, и
> устаревший датчик никогда не снимает тревогу.
| `ota` | string | — | **убран в v1.14.0** — у сборки с Zigbee единственный раздел приложения и нет слотов OTA; ключ игнорируется |

> **`ota` — единственное поле, способное запустить код.** Телеметрия идёт
> нешифрованным TCP без аутентификации по локальной сети, поэтому прошивка не
> принимает URL на веру: `OtaManager::urlAllowed()` соглашается только на
> настроенный хост телеметрии (`PC_IP`) либо на литерал из RFC1918/петли и
> отвергает любой authority, содержащий `@`. Всё прочее отклоняется и
> показывается тостом.

## `claude` — отдают ОБА производителя, и каждый свою половину

| ключ | кто отдаёт | значение |
|---|---|---|
| `win` / `wk` | lite (настоящие), хаб (ретранслирует из lite) | НАСТОЯЩИЕ проценты расхода за 5 ч / 7 дн из заголовков Anthropic `anthropic-ratelimit-unified-*` |
| `rst` / `wrst` | они же | минут до сброса окна 5 ч / 7 дн |
| `plan` | они же | подпись подписки, например `max 5x` (множитель уровня свёрнут из `rateLimitTier`) — бейдж на экране |
| `tok` / `msg` / `tool` / `day` | **только хаб** | счётчики из стенограмм Claude Code, читаются из `~/.claude` на ПК |
| `ok` / `stale` / `src` | оба | `src` — это `live` (настоящий API) / `sessions` / `stats-cache` |

Настоящие проценты может отдать только машина со свежим OAuth-токеном Claude, а
это редко ПК: это тот хост, который обновляет токен. Он публикует их в
маленький JSON-файл, а сервер ретранслирует через `claude_remote_url`. Никогда
не копируйте эти учётные данные на вторую машину — два обновляющих гонятся за
ротацией refresh-токена, и проигравший начинает раздавать просроченные.

> **Прошивка СЛИВАЕТ этот блок, а не заменяет его** — отсутствующий *или*
> `null` ключ оставляет прежнее значение в покое. Именно это и позволяет одному
> производителю давать проценты, а другому счётчики. Производитель, желающий
> сказать «не знаю», обязан опустить ключ; присланный `0` утверждает ноль.

## Слишком длинные кадры

Строку длиннее `NOCT_TCP_LINE_MAX` (4096) разобрать нельзя. Хаб
(`encode_payload`) сбрасывает необязательные блоки по возрастанию ценности —
`notif`, `tp`, `tr`, `wf`, `fan_controls`, `fans`, `hdd`, `events`, — пока кадр
не влезет; `claude`, `forest`, `svc` и скаляры железа не выбрасываются никогда.
Если и этого не хватило, он не шлёт **ничего**, и устройство остаётся с
последним хорошим состоянием. (Раньше он заменял весь пакет на `{"ct":0,…}`,
чем одновременно терял два самых ценных блока и затирал живые показания
железа нулями.)

## Устройство → сервер (обратный канал)
- `HELO` / `HELO <токен>`, `screen:N`, `cmd:claude|status`. Приветствие — ПЕРВАЯ
  строка каждого соединения. Хаб с заданным `board_token` читает её и отбрасывает
  всё, что не `HELO <его токен>`, в пределах пяти секунд — это единственный
  рубеж, который есть у голого TCP-порта в открытом интернете. Хаб без токена
  принимает короткую форму, а приветствие с токеном считает неизвестной строкой
  обратного канала, так что одна плата ходит между обоими без перепрошивки.
  Токен берётся из `[server] token` на карте; `server <хост> [порт] [токен]` в
  консоли USB туда его и пишет.
- `wolf:` — статы питомца (сытость/радость/энергия/настроение/жив/спит/возраст)
- `zbs:` — по строке на каждый локально привязанный датчик Zigbee, раз в минуту:
  `zbs:имя,темп10,влажность,заряд,возраст_сек,давление_гПа` (температура ×10;
  -1 = неизвестно; имена берутся из `nocturne.ini` и не должны содержать
  запятых). Так сервер — а через него и навык Яндекса для умного дома — узнаёт,
  что слышит координатор.
- `zbs:` получил шестое поле в v1.16: `…,возраст_сек,давление_гПа` (-1 = у
  датчика нет барометра). У Aqara WSDCGQ11LM он есть, у WSDCGQ01LM нет, так что
  потребитель обязан считать поле необязательным, а не предполагать ноль.
- **Разбирайте эту строку СПРАВА.** Хвостовые поля — все целые, а имя это всё,
  что им предшествует, так что снимайте целые с конца, а не режьте по
  фиксированному числу полей. Необязательная ветка `motion-sensor` дописывает
  ещё два (`lux,возраст_движения_сек`), и потребитель, снимающий ровно пять с
  такой строки, вернёт имя как `ForestHome,230,56`, а температуру — как заряд.
  Молча. Фиксированное число полей — это обещание между двумя репозиториями,
  которое в момент исполнения никто не проверяет.
- `zbs:` несёт ТОЛЬКО те датчики, которые этот координатор услышал на СВОЁМ
  радио. Датчик, ретранслированный сервером или вписанный из консоли, наверх не
  возвращается никогда. Строка означает «что слышит плата», сервер так её и
  хранит, а ретранслированная запись, отчитанная обратно как локальная,
  заставляет плату выдавать чужие данные за собственное наблюдение — и потом это
  два часа висит в панели устройством, которого нет и которое нельзя убрать.
  Плата считает это как `ZigbeeData::localCount`, записанный ДО слияния с
  ретранслированным: после слияния они неразличимы.
- `zbw:` — все окна анализа разом, каждый раз, когда плата пересчитывает
  (раз в 5 мин):
  `zbw:dew10,pressPct,dP1,ok1,dP3,ok3,dP6,ok6,dP12,ok12,dP24,ok24,dT1,dT24`
  и, ДОПИСАННОЕ в v1.26 (поля 15..27, именно дописанное, а не вставленное, так
  что потребитель, который режет и игнорирует хвост, продолжает работать):
  `absHum10,tempPct,humPct,dT3,okT3,dT6,okT6,dH1,okH1,dH3,okH3,dH24,okH24`.

  У собственных показаний комнаты окон на этой строке не было вовсе — по
  влажности ни одного, по температуре только 1 ч и 24 ч, — то есть всё, что
  датчик посреди комнаты мог сказать о комнате, вычислялось и выбрасывалось.

  `absHum10` — это десятые доли грамма воды на кубометр, -9999, когда вычислить
  нельзя. Он существует потому, что ОТНОСИТЕЛЬНАЯ ВЛАЖНОСТЬ НЕ ЯВЛЯЕТСЯ МЕРОЙ
  ВОДЫ: это отношение к ёмкости, которая примерно удваивается каждые десять
  градусов, так что она падает, когда включили отопление, и ничего при этом не
  высохло. Потребителю, которому нужно «случилось ли что-то в этой комнате»,
  читать надо именно это, а не RH. Дельты влажности (`dH*`) — в целых процентах,
  не в десятых.
  Дельты — в ДЕСЯТЫХ (гПа, градусов). `dew10` — точка росы по Магнусу, -9999,
  когда вычислить нельзя. `pressPct` — то, где текущее давление стоит в
  СОБСТВЕННОМ накопленном распределении платы, -1, когда архив ещё слишком
  короток; абсолютный уровень не выгружается вовсе, потому что датчик отдаёт
  давление станции, а приведение к уровню моря требует высоты, которую никто не
  вводил.

  **У каждого окна свой флаг ok, и потребитель обязан его уважать.** «На карте
  ещё нет истории такой глубины» и «за это окно ничего не изменилось» — разные
  ответы, и принять первый за ноль — это ровно тот способ, которым график
  рисует уверенную прямую через промежуток, по которому данных у него не было.

- `zbpat:` — один сработавший шаблон, шлётся сразу после `zbw:`:
  `zbpat:id,severity,заголовок|подробность`. `id` — это перечисление
  `analysis::PatternId`, `severity` — 0 стоит знать / 1 стоит взгляда / 2 стоит
  того, чтобы прервать. id и severity идут первыми, чтобы потребитель мог
  маршрутизировать по ним, не разбирая русский текст, который написан только для
  людей. Свежий `zbw:` обесценивает каждый `zbpat:` до него: пара — это один
  неделимый отчёт.

- `zbcsvb:` / `zbcsv:` / `zbcsve:` — климатический архив, передаётся по запросу
  (`zbdump`). Начало несёт число дней, затем по строке на показание в виде
  `zbcsv:ГГГГ-ММ-ДД,ЧЧ:ММ,темп_c,rh,бат,давл_гПа`, затем `zbcsve:строк,полнота`.

  Плата отдаёт это примерно по 20 строк за 100 мс; выгрузка не блокирующая.
  `complete` равен 0, когда обход был брошен, и потребитель **обязан** отбросить
  неполную передачу, а не сливать её — усечённый архив, поданный как целый, это
  ровно то, на чём потом строят прогноз и тихо в нём разочаровываются.

  Строки могут повторять отметку времени: датчик отчитывается по каждому
  атрибуту отдельно, и каждый пишет полный снимок, так что примерно 40 % строк
  делят минуту с другой. Сливайте по отметке времени, побеждает новейшая.
  Проверяйте форму полей даты и времени, прежде чем верить строке: строка TCP
  может прийти разорванной, а испорченная запись внутри архива — это точка
  данных, которой никогда не существовало.

  **Источник истины — карта, а это зеркало.** Плата пишет показание независимо
  от того, слушает ли кто-нибудь; потребитель слышит его только пока подключён.
  Значит, ночь с выключенным ПК оставляет дыру в зеркале и не оставляет на
  карте, и чинится это всегда повторным забором, а не достраиванием из того, что
  прилетело вживую.

- `brd:` — собственные показатели платы, каждые 15 с:
  `brd:temp,temp_max,load,fps,heap_free_kb,heap_min_kb,heap_largest_kb,
  uptime_s,cpu_mhz,rssi,boots,faults,bl_now,bl_cap,bl_thermal,bl_force_left,
  reason`. Устройство целый день следило за ПК и не сообщало о СЕБЕ ничего — то
  есть узнать о нём можно было, только когда оно остановится. `load` — это доля
  периода кадра, которую цикл отрисовки действительно провёл в работе: у скетча
  Arduino нет учёта планировщика, который можно спросить, так что это
  единственная цифра, которую можно измерить, а не выдумать, и подписана она как
  загрузка цикла, а не процессора. `heap_min` важнее, чем `heap_free`: именно
  нижняя отметка решает, поместится ли следующее рукопожатие TLS.

  Четыре поля `bl_*` (v1.33.0) говорят, что подсветка ДЕЛАЕТ на самом деле, в
  отличие от того, что попросил ползунок: `bl_now` — подаваемый PWM, `bl_cap` —
  действующий потолок, `bl_thermal` — 0 холодно / 1 ограничено по теплу /
  2 ограничено по жаре, `bl_force_left` — секунды, оставшиеся у временного
  переопределения. Ночной режим, гашение по простою, тепловой гвард и
  переопределение молча перебивают запрос, так что без этих полей владелец
  читает на панели 210, пока стекло стоит на 90, и ничто одно с другим не
  связывает.

  Они вставлены ПЕРЕД `reason` намеренно. Причина — свободный текст и может
  содержать запятые, так что приёмнику, режущему справа, пришлось бы знать,
  сколько их несёт сообщение о панике. Разбирающему следует определять новую
  форму по СОДЕРЖИМОМУ — четыре целых там, где им положено, — а не по числу
  полей.
- `zbtr:` — барическая тенденция за 3 ч, раз в 5 мин:
  `zbtr:dДавл_десятые_гПа,dТемп_десятые_c,dВлаж_проценты`, считается по архиву на
  карте, а не по двум последним отчётам. Шлётся отдельно от показаний, потому что
  **погоду предсказывает скорость, а абсолютное давление говорит лишь о вашей
  высоте над уровнем моря.** Три часа — метеорологический стандарт: именно эту
  тенденцию отдаёт METAR, и именно к этому интервалу привязан каждый
  опубликованный порог.

  > Давление — единственное показание здесь, которое про УЛИЦУ. Здание не
  > герметично, так что давление внутри следует за атмосферным с точностью до
  > долей гПа — поэтому барометр в комнате предсказывает погоду, тогда как
  > комнатный термометр всегда описывает только батарею. Дельты температуры и
  > влажности едут рядом для полноты; не стройте на них погодных выводов.
- `zbst:` — отчёт координатора о самом себе, каждые 15 с:
  `zbst:up,канал,осталось_окна_сек,устройств,слышали_сек_назад` (-1 = не слышали
  никогда). Поднятый хаб без датчиков и лежащий хаб выглядят снаружи одинаково, а
  чинятся по-разному — поэтому плата сообщает, что именно из двух, вместо того
  чтобы оставлять панель домысливать это по молчанию.
- `sd:` — здоровье карты, раз в минуту:
  `sd:ok,частота_Гц,занято_МБ,всего_МБ,записей,медленных,сбоев,очередь,последняя_мс`.
  Плата — единственное, что видит собственную карту, так что без этого карта,
  тихо завалившая сорок записей, выглядит точно так же, как здоровая, пока
  кто-нибудь не откроет архив и не найдёт в нём дыру.
- `cfg:` — CSV-зеркало настроек устройства, чтобы панель отражала плату.
  **Тридцать пять полей с v1.43.0** — список ключей в панели обязан совпадать
  позиция в позицию, потому что короткий список молча теряет хвост (что и
  случилось с `pinned`/`slot`/`night*` до v1.14.1).
  Поля, по порядку:

  `petllm, wchat, wtone, led, flip, bglight, bright, carousel, timeout,
  bgstyle, theme, uielem, scenemask, notifshow, ledmode, pin, slot, night,
  nightfrom, nightto, zbalert, zbtmin, zbtmax, zbhmin, zbhmax, zbbat,
  carmode, carfreq, dots, pet, kind, furry, style, ledbright, web`

  (`carfreq` — строка из двадцати цифр, по одной на сцену в порядке SceneId.
  Поля 30–35 дописаны в v1.43.0.)

  `carousel` равен -1, когда выключена; `theme` равен -1, когда активна своя
  палитра. Поля 16–20 были **дописаны** в v1.9.0 — панель, которая режет по
  индексу и игнорирует хвост, продолжает работать. Здесь можно только
  дописывать и никогда не переставлять.
